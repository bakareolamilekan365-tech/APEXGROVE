# Plain-language glossary

| Term | Simple meaning |
| --- | --- |
| API | A controlled way for one part of the product to request information or an action from another part. |
| Audit | A review of what exists, what works, what is risky, and what still needs proof. |
| Audit log | A history showing who performed an important action, what changed, and when. |
| Authority level | Whether information is user-supplied, automatically checked, reviewed by Atexgrove, reviewed by a professional, confirmed by an authoritative third party, or officially/statutorily confirmed. |
| Consent record | Evidence of who agreed, when they agreed, what they were told, and which version of the terms or notice applied. |
| Controlled pilot | A limited Abuja/FCT service tested with selected participants and carefully restricted claims, evidence and responsibilities. |
| Database migration | A numbered change to the structure or rules of the database. |
| Document version | A preserved edition of a document. A replacement becomes a new version instead of silently erasing important earlier evidence. |
| Docker | Software used to run a complete temporary development environment on a computer. GitHub Actions currently performs this role for Atexgrove. |
| E2E test | A test that follows a complete user journey from beginning to end. |
| Evidence | A document, observation, source, or record used during verification. |
| GitHub Actions | Automated checks that run when code is proposed or updated. |
| GIS | Technology used to store, display, and work with location and map information. |
| Hosted project | The online Supabase environment connected to the application. |
| Migrations `015`-`017` | The merged and hosted database changes that strengthen foundation security, private storage and organization-owner protection. Their pgTAP tests passed in a temporary GitHub Actions environment; hosted operational checks and advisor follow-up remain open. |
| pgTAP | A tool for testing database behavior, including what users are allowed or forbidden to do. |
| PostGIS | A database extension that adds map and geographic capabilities. |
| PR | A pull request: a proposed group of changes reviewed before joining the main codebase. |
| Provenance | Information explaining where data came from, when it was collected, and who supplied or reviewed it. |
| RLS | Database rules that decide which records each signed-in person may access. |
| Second review | Review by a genuinely separate, appropriately qualified person before a consequential conclusion is delivered. It is not the same as official government confirmation. |
| Supabase | The managed service providing Atexgrove's accounts, database, and file storage. |
| Vertical slice | One small feature built completely from stored information and permissions through to the user interface and tests. |
| Verification | A controlled review process; it does not automatically mean government or legal confirmation. |
